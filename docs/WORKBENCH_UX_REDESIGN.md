# OptiProp 工作台：操作流程重新規劃

狀態：v1.0.8 本機瀏覽器工作台發布範圍 + Draft 2 後續 UX 規劃。日期：2026-09-15。

### v1.0.8 發布範圍與相容性

本版入口是 `optiprop-workbench`，使用 `optiprop.workbench.app` / service 與隨套件
分發的 static 資源，透過 Python 標準函式庫 HTTP server 在 loopback 啟動本機瀏覽器。
不需要 Qt、額外 Web framework 或 Node.js；不是遠端託管服務，不應暴露到外部網路。
`optiprop-gui` / `optiprop.gui.launch()` 是薄轉接入口，`[gui]` extra 保留但為空。

本版範圍為 source、順序光路設定及執行、理想/Binary2 透鏡、Ex/Ey 檢視、XZ 掃描、
canonical JSON 專案及 MAT/NPZ/ZBF 場資料流程，不宣稱已完成自由相位最佳化、完整
資料庫編輯器、固定幾何多波長比較或此文件全部互動驗收案例。
四份 canonical JSON 範例隨 wheel / sdist 分發於 `optiprop/workbench/examples/`；
準直範例採解析光源，不包含私人量測檔。Windows portable build 使用 CPU PyTorch；
Linux Python 安裝可使用該環境已安裝的 CPU/CUDA PyTorch。

整理版已移除舊 Qt 實作與 widget tests，不刪除原始母目錄的舊 UI 或使用者專案。
舊 Qt 扁平表單 `.oprop` 格式不會靜默轉成 canonical domain；請保留原檔，在新工作台
重建或從 canonical 範例開始，需要舊 UI 時使用原始工作副本 / v1.0.7。

以下第 0–11 節保留作為操作規則與後續驗收目標，並非全部已實作的功能清單；
發布範圍以本節與 README 為準。舊 `NEAR_FIELD_UI_IMPLEMENTATION_PLAN.md` 的數值
核心規格可供歷史參考，不再是新版 GUI 安裝或啟動說明。

## 0. 本輪修正：軟體是通用光路編輯器，不是準直專用流程

使用者決定光源、傳遞順序、每段距離/介質/演算法，以及要經過哪些元件。
系統只按設定執行及驗證，不自動猜用途、不強制加入 lens、不强制做最佳化。
雷射準直是一份可載入的範例 JSON，與使用者自己儲存的專案同等，不寫進主介面。

預設開啟空白專案：一個可設定的 source，零個下游操作。按「新增傳遞」或
「插入元件」建立線性的操作序列，例如：

`source → 傳遞 100 µm → 孔徑 → 傳遞 200 µm → phase mask → 傳遞 1 mm`

不設定任意元件数量上限；实际可計算规模受取樣、記憶體與後端限制。
第一版是順序傳遞，不暗中承諾分光、分支合束、任意反射或完整 3D 光線追跡。

### 光路編輯的單一操作規則

- 選中一列後，在該列之後插入；沒有選中時加到末端。source 永遠是起點。
- 「傳遞段」擁有距離、介質、方法及 sampling/padding 設定。
- 「元件」擁有自身振幅/相位/孔徑/界面參數，不另外偷藏傳遞距離。
- 薄元件只改變場，不增加 z；段距離的總和決定位置，不能再維護一套矛盾的絕對 z。
- 拖移與上下移動皆可；停用一段時整段距離也不作用，UI 顯示「略過含距離」。
- 想保留間距但拿掉元件：只停用該元件，而不改相鄰傳遞段。
- 每列顯示名稱、類型、z 前/後、介質與摘要；點選後才顯示適用的編輯欄位。
- 修改介質不代表已處理界面反射；不匹配時提示新增界面或明確模型設定。
- 支援刪除、複製與 Undo；刪除有監測器引用的列時先提示，不自動改綁到別列。

### 監測器與運算

每個步驟的輸入/輸出都可查看；額外監測面可綁定某個步驟 UUID + before/after + offset。
插入、移動元件後，監測面跟隨明確引用，不以「第3列」作永久識別。
要沿完整系統看任意 z，需經過該 z 之前的所有元件；不能從 source 直接穿越元件傳過去。
額外監測器不參與操作序列，不讓後续元件被重複傳遞一次。

主要執行入口是「計算到此步驟」和「計算完整光路」；單獨傳播不需先建立設計目標。
「新增 XZ 掃描」「多波長掃描」「最佳化選中元件」是選用分析工具，不是主流程必經站。

### JSON 是使用者專案，不是介面專屬的範例設定

- 同一個 loader 載入內建範例與使用者專案，載入後可以任意增刪元件與傳遞段。
- 空白/開啟 JSON/載入範例是三個入口，不把準直自動當起始內容。
- 範例在 `Example/projects/`；JSON 儲存版本、source、ordered layers、計算設定、
  穩定 UUID、資產引用，以及已支援的 UI/metadata；SI 作序列化單位。
- 沿用 canonical `optiprop-project` schema v1、`IncidentSource`、`OpticalSystem`
  與 `PropagationLayer` 等類型，不另造只為本畫面服務的不相容 JSON。
- 新的監測器、最佳化任務、moving-window 等若尚未有正式序列化/執行支援，先列為
  待接入能力，不塞進 metadata 後宣稱已能執行；擴充需版本化與 migration。
- 場檔和資料庫使用資產引用，不把大型 complex arrays 塞進 JSON。缺少資產可開啟設定，
  但阻止相關計算並提供重新定位。
- `free_propagation.json` 是自足的傳遞範例；`laser_collimator_demo.json` 是可跑的
  解析 Gaussian 示範，不是 P3_10um 私人光源的重現。真實光源版需經過匯入與資產驗證
  再另存，不使用虛構 SHA256 或假裝存在的檔案。
- `metalens_focus_ideal.json` 是平面波 → 理想相位 Metalens → ASM 焦平面傳遞的
  自足範例（1310 nm、D=60 µm、f=100 µm）。同一編輯器可載入，不增加專用工作流程。
  它不含 meta-atom 查表或 full-wave 效應；獨立 Python 範例可計算 Ex/Ey 焦平面及 XZ 圖。
- 舊 Qt GUI 的扁平表單格式與 canonical domain 格式有落差；新版直接使用 canonical
  adapter，不承諾舊 `.oprop` 自動遷移。保留舊檔，另行重建或使用 canonical 範例。

## 1. 產品定位與成功標準

定位：使用者自行組合光源、傳遞段與元件的「通用光場工作台」。
只傳播、孔徑繞射、多片透鏡、任意 mask 等都是普通專案；準直沒有特殊主流程。

使用者應始終知道：正在編輯哪個實驗、看到哪個位置、哪個版本、哪次計算。
主要動作使用物理語意，例如「計算到孔徑 A 的輸出」，不只顯示 Run。

首要通用驗收任務：

1. 從空白建立「source → 傳遞 → aperture → 傳遞」，不用設計任何 lens。
2. 在任意位置插入第二個元件、修改距離、移動/停用，位置與監測器引用保持一致。
3. 儲存再載入 JSON，順序、SI 參數、ID 與元件響應不變。
4. 從範例 JSON 載入準直專案，刪除透鏡後仍是一份合法的普通傳遞專案。

準直範例的回歸驗收任務（不是所有專案都需完成）：

1. 新使用者不用改 Python，完成成對 Ex/Ey 載入、65 µm 膠水傳遞、指定觀察面。
2. 複製設計，比較理想相位與共用自由相位，不重新填相同光源設定。
3. 固定 1310 nm 選出的柱子，用 1290/1330 nm 資料庫評估，不意外重新排列。
4. 找到透鏡前與透鏡後 0.2 µm 的 Ex/Ey，完成 MAT/ZBF 匯出，不找結果資料夾猜檔案。
5. 65 改成 40 µm 後，清楚知道哪些舊結果不再對應設定；不遺失之前的比較。

以上是可測試的任務，不先承諾未量測的完成秒數或點擊次數。

## 2. 三種物件，不再混在同一張表

| 物件 | 內容 | 修改方式 |
| --- | --- | --- |
| 實驗 | 光源資產、光路、介質、參考座標、觀察定義 | 編輯草稿、自動儲存、可復原 |
| 設計版本（選用） | 某個元件的相位、振幅模型、幾何配置及設計波長 | 複製比較；已使用版本不被悄悄替換 |
| 計算紀錄 | 不可變設定快照、輸入檔指紋、軟體版本、產生的結果 | 新計算產生新紀錄；可釘選、重新開啟 |

「另存設計」不是再複製數百 MB 光源；同一資產可以被多個版本引用。
觀察面/掃描是讀取光路的探針，不是會額外改變系統的光學元件。

## 3. 導覽：以光路編輯為主，不強制走設計流程

主畫面：**光路順序 + 選中列的屬性 + 觀察結果**。
結果紀錄可獨立打開比較/匯出；工具選單才放設計、最佳化、參數與波長掃描。

- 初次建立時提供下一個建議動作；任何時候可返回修改，不鎖住分頁。
- 每個工作區只有一個主要動作；未滿足條件時就地顯示原因與修正入口。
- 不在一開始顯示所有後端方法、GPU 選項、loss 權重與檔案格式映射。
- 全域顯示實驗名稱、設計版本、計算狀態。實際結果區另外顯示計算 ID。
- 不做自由連線的節點畫布作為預設。多層光路用有順序的清單，可新增、移動、停用，
  並提供鍵盤操作；相鄰介質與座標重新驗證。
- 開始頁提供「開啟 JSON」「載入範例」「空白光路」。預設不選任何範例；
  自由傳播、準直等並列，沒有強制準直教學。

## 4. 工作區一：光路

### 4.1 匯入光源

使用者可以一次選取 Ex/Ey 的 irradiance/phase 檔，或選一個 ZBF/MAT/NPZ。
系統提出檔名配對，但要確認，不能只凭檔名判定振幅、強度或相位單位。

一次匯入確認頁包含：

- Ex/Ey 與 I/phase 對應，來源波長、來源介質。
- 原始 Nx/Ny、dx/dy、空間單位、中心、軸方向、相位 rad/degree、I 或 amplitude。
- Ex/Ey 振幅與相位四格預覽，翻轉軸的預覽與確認。
- 原始與計算網格分開列出；預設保留，不靜默重新取樣。
- 不一致的網格或缺少 metadata 顯示「待確認」，不靠猜測填入。
- 單分量合法；不存在的 Ey 顯示「未提供」，不畫成像有量測的結果。
- 儲存可重用的格式映射；不在每次開啟時重填。

只做相位顯示遮罩，不修改原始光場。弱光區相位不可靠，預覽要明確遮罩，
門檻可調且顯示。物理功率單位尚未確認前，不把相對強度標成 W。

### 4.2 建立光路

通用操作以第0節為準。以下只是準直範例的代入值：
source(z=0) → glue(n=1.5, distance=65 µm) → lens → air → output。
65 µm 只來自該範例 JSON；全域不預設膠水、透鏡或此距離。

- 點選介質段，編輯「長度」與「折射率」，而不是新增一個叫 propagation 的不明項目。
- 點選薄元件，編輯直徑、中心、相位來源；基本欄位使用 nm/µm/mm，內部仍為 SI。
- 顯示累積全域 z 與距離參考點。0.2 µm 應標為「相對 lens 出口面」，不是不明的 z。
- 透鏡前與透鏡後是不同狀態，即使兩者幾何 z 相同。前者在膠水，後者介質須確認。
- n=1.5 到 n=1 的界面不能因改了 n 就宣稱已處理反射。
  顯式選擇介面模型或忽略反射；資料庫是否已包含界面響應須確認，避免重複乘傳輸。
- 「計算透鏡前光場」先檢查來源、取樣、記憶體估計與介質，再提交可取消任務。

進階折疊區：方法、padding、dtype、device、evanescent 政策。不能把更換
propagator 當成無影響的外觀設定；所有計算選項都寫入紀錄。

## 5. 選用工具：設計特定元件

### 5.1 先選目標，再選設計方法

先選要設計的元件與評估位置，再選任務：準直、聚焦或指定目標光場。
「只跑傳播」不需要先做設計。

準直必須區分：指定面平坦相位、傳播後光斑形狀、遠場/角譜發散。
單一面的相位平坦不等於有限孔徑光束永遠不發散。

方法是同一設計工作區的選項，不是三支分開的程式：

- 解析理想相位：模型、焦長、參考介質、參考波長都明示。f=26.6 µm 只是
  起始設計參數，不標為已達成的準直效果。
- 輸入光場補償/既有 adjoint 方法：先審核 Example 的實際目標函數，給出準確名稱；
  不把共軛相位、自動微分與 adjoint 一概當成同一演算法。
- 自由相位最佳化：明確選可調相位、孔徑、空間平滑/製程限制、評估面。
- 匯入自訂 phase/complex mask：檢查單位與網格，預覽後套用。

Ex/Ey 預設共用一張 scalar phase；UI 顯示目前選的是共用相位而非兩片透鏡。
純相位薄元件在同一平面不改變振幅，也不能改變 Ex/Ey 的相對相位差；裁切孔徑會
改變振幅但損失能量。若希望改變分布，需要後續傳播、振幅自由度或其他物理機制。
因此不能保證任意 Ex/Ey 同時完美圓形且平相位。

最佳化的必要輸入：

- 評估面：相對哪個元件、距離、介質。不得暗中給未指定的 downstream 距離。
- 圓形目標：總強度還是 Ex/Ey 各自、目標寬度、觀察 ROI。
- 相位目標：強度加權的 wrapped-phase error，排除低光區並去除全域 piston；
  是否允许整體傾角必須明示。
- 偏振平衡：起始建議各分量內正規化、等權，另顯示總功率加權指標；
  權重可調，不能讓較弱的分量被隱藏。零功率分量有明確處理。
- 成效同時看相位誤差、角譜發散、光斑寬度比及有效區能量，避免只看 loss。
  每個指標必須定義 ROI、分母與單位；不能混稱圓形度或效率。
- 顯示迭代、best-so-far 與曲線；取消時保留已保存最佳解。不宣稱未實作的暫停續跑。

### 5.2 相位設計與 meta-atom 實現是兩層

先建立「理想相位設計」，再選擇是否「用資料庫實現」。兩者並存供比較。

資料庫確認頁：幾何參數/單位、設計波長、period、厚度、polarization channel、
transmission 是 field amplitude 還是 power、可信來源。未知不得靜默採用。
若支援 pickle 型 .npy，先提示只載入可信檔案，不把任意上傳檔直接反序列化。

使用固定柱子做其他波長分析時：

- 複製幾何 map 或穩定 geometry ID，不複製資料庫 row index。
- 依 R/其他幾何參數、period、厚度與通道尋找同一幾何；排序不同不影響選擇。
- 缺少幾何或資料庫条件不匹配時列出清單，預設停止，不偷偷改成 nearest phase。
- 若允許插值，需另行支援與確認，標記為估計；不能冒充資料庫中的原始響應。
- 單波長相位 map 不能自行推論其他波長相位。理想模型要選固定相位 mask 或
  固定 OPD 等明確色散假設；自動微分/任意 phase 也不能假設天然具有色散模型。
- 光源波長變化若沒有對應 Ex/Ey 檔，可以明確勾選「沿用 1310 nm 空間複數場」作假設，
  並把此限制印到結果/匯出紀錄。

## 6. 結果檢視與比較

預設先看到光場，不先看到大張統計 dashboard。固定顯示目前的：
實驗/設計/計算 ID、真空波長、介質、觀察點、計算網格、資料來源。

- 觀察面直接從任意列的輸入/輸出選取，或新增參考該列的監測器；
  source、lens−、lens+、lens+0.2 µm 只是準直範例，不是固定選項。
- 預設 Ex/Ey 並排，amplitude/phase 兩列；可改為 intensity/XZ，但不默默只顯示 Ex。
- 振幅是 source 通過 lens 後的場，不是 lens transmission。元件本身的 T(x,y)
  有獨立的「元件響應」入口與圖名，永遠不混稱。
- 複製 baseline 產生設計 B；釘選 A/B 後比較。圖面明示是否同一網格與位置。
- 共用範圍、單位與 color scale 是預設；若逐圖正規化需顯著標示，不掩蓋透射差。
- 為保持精度，預覽降採樣与完整數值分離，任何圖上量測註明取樣來源。
- 純粹切換色盤/視圖/既有觀察面不重新運算。缺少該面資料才提供「計算此面」。
- XZ 的 Ex/Ey 各一 subplot，可固定/移動視窗、局部/全域座標；切片 y 與 z 參考点明示。
- 移動視窗只允許已支援的 ASM 組合；禁用 shifted BLAS、傾斜面與變倍率的冒充選項。
  顯示 padding/週期副本風險；移動視窗不等於自動消除 aliasing。

波長掃描從已凍結設計啟動；總表區分成功、失敗、取消與未計算的波長。
掃描不覆蓋原設計；參數掃描（例如 40/65 µm 或焦長）同樣記錄每個條件。

## 7. 從結果匯出

從明確選中的計算紀錄出發，而不是從目前草稿出發。已過期的舊計算仍可刻意匯出，
但必須顯示舊設定；不能把新草稿參數寫進舊場的檔案。

第一頁只問：要哪些觀察面？MAT/ZBF/NPZ/圖？存在哪裡？
進階欄位按格式出現。

- 預設選中目前查看的已計算觀察面；其他面由使用者勾選。
  準直範例可另帶 lens− 和 lens+0.2 µm preset，不套用到其他專案。Ex/Ey 同檔輸出。
- MAT：EX/EY 使用 complex128；dx、dy（公尺）、Nx、Ny、座標/波長/介質 metadata；
  資料陣列 `[Ny,Nx]`，維度對應顯式驗證。轉成 double 不代表先前低精度運算被提升。
- ZBF：長度欄位按格式統一換算 mm；Nx/Ny 各為 2 的次方，不要求彼此相等。
- 非二次方時阻止直接輸出，提供顯式 zero-padding（保留 dx/dy）或另行重取樣；
  顯示新視野/中心座標與 field of view 變化。不能只改 header。
- 奇偶維度補零可能導致半像素的中心約定差異，必須以座標/場值測試驗證，
  不在匯出時靜默移動光束；無法保留既有座標時須說明可選策略。
- 預覽矩陣大小、dx/dy、波長、介質、z、單位與所選 Ex/Ey，再執行匯出。
- 圖片 preset：投影片/論文，字級、colorbar 與每個 y-axis 等高、Ex/Ey subplot，
  可選固定色階；不用修改 plot 原始碼。
- 每批匯出附 manifest，包含計算 ID、真實精度、後處理/補零、原始檔指紋。
- 輸出以 `output/<experiment>/<run-id>/` 管理；不依賴難辨的 output1/output2 名稱。
  舊 output1/output2 不搬動、不刪除、不覆寫；可另建可追溯的索引。

## 8. 狀態、錯誤與快取

草稿自動保存不等於自動運算。修改欄位後等待明確提交；不每打一個字跑一次 GPU。
支援 Undo/Redo 與欄位級錯誤，結果不因暫時的無效输入消失。

計算狀態：未計算 → 排隊 → 計算中 → 完成/失敗/已取消。
設定變更不是把完成結果改成錯誤，而是將目前草稿標成「與 r001 不同」。

| 改動 | 預期需要更新 | 可保留 |
| --- | --- | --- |
| 色階、標題、投影片字級 | 圖片 | 全部場資料 |
| 新增 lens 後觀察距離 | 新觀察場 | 既有 lens 出口場 |
| 透鏡相位或幾何 | 透鏡及下游 | 已驗證相同設定的入射場 |
| 膠水距離/折射率 | 透鏡前及下游，並標記補償設計輸入改變 | 舊計算紀錄 |
| 光源、波長、網格 | 所有受影響計算 | 未受影響的獨立紀錄 |

不可直接假定所有快取皆已可用：先定義來源檔指紋、完整物理/數值設定、軟體版本，
再實作依賴鍵與失效測試。GPU 任務一次一個為初期策略，避免多任務互搶記憶體。
記憶體/時間為估計，不用假的精確進度或預計完成時間。

錯誤訊息提供位置、原因、可做的修正，例如「Ey 網格不同：查看映射 / 明確重取樣」。
專家可展開日誌；新手不用讀 traceback。取消只停止任務，保留已完成紀錄；
刪除紀錄/資產是另一个需要確認且提示引用關係的動作。

## 9. 實作切分與遷移

v1.0.8 採本機 Web UI。前端處理操作與圖形呈現，Python service 負責 canonical
系統建立、運算與匯出，保留 PyTorch 核心及數值測試。整理版已移除
`gui/simulation.py` 的 Qt worker；`gui/app.py` 與 `gui/__init__.py` 僅保留轉接。
瀏覽器後端測試位於 `tests/workbench`，相容入口測試不需要 Qt。
下列更完整的工作台流程仍須逐項驗收，不代表快取、版本比較與最佳化已完成。

本機服務只綁 loopback；使用啟動期憑證與 Origin 驗證，資產目錄由使用者選定。
不要為了預覽把整份複數張量轉成巨大的 JSON，不向外部服務傳送光源。
前端 static 資源與 canonical 範例隨一般套件分發；不需另外安裝 GUI/Web 依賴。
Windows 提供 CPU portable build 的封裝方向；遠端運算與多人協作不屬於本版。

交付順序（每個階段以操作驗收為前提）：

1. **互動草稿**：用上述首要任務確認操作語意、畫面密度與位置辨識；不使用假模擬結果。
2. **真實最小流程**：通用 source/有序操作新增編輯 → 計算到所選步驟/完整光路 →
   Ex/Ey 觀察 → MAT/ZBF → JSON 重開；可選零片或多片元件，不要求相位設計。
3. **設計與比較**：版本/計算快照、既有補償方法接入、固定幾何多波長、ASM 移動視窗。
4. **自由相位最佳化**：明確的目標/約束、取消/最佳解、可重現驗證；不先用大量進階表單塞滿畫面。

新工作台使用獨立入口，舊命令轉接至新入口；舊數值 API、範例及使用者原始專案保留。
本版不執行舊 Qt 格式 migration；未來若新增 migration，必須版本化並保留原檔。
此文件只記錄發布範圍，不代表 GitHub 發布或遠端更新已執行。

## 10. 互動驗收案例

- 透鏡「理想 / Binary2」切換：同一元件 ID、共用孔徑，保留各模型參數；下游距離不变。
- Binary2 以 C1(r²)、C2(r⁴)…編輯，標示 rad/mm^(2i)，支援增減項；全零明示平坦相位。
- 理想焦長與 Binary2 係數不是無損互轉；首次手動切换不自動擬合，兩組設定各自保留。
- JSON 的有效層使用 `IdealLensLayer` / `Binary2LensLayer`；未啟用模型暫存在
  `ui_state.lens_model_drafts[UUID]`，不參與物理計算。複製、Undo、重新載入保留草稿。
- Binary2 與舊 `Binary2Phase` 數值相容，不按波長/折射率暗中縮放；同一 scalar T 乘 Ex/Ey。
- `metalens_focus_binary2.json` / `Metalens_Focus_Project.py --phase-model binary2`
  提供可實際執行的四項 Taylor 聚焦範例，非兩階量化、非資料庫真實透鏡。
- 匯入 Ex/Ey 維度不同：不允許假裝載入成功，可返回 mapping 修正。
- 修改 65 → 40 µm：已釘選 r001 圖不變，草稿顯示需重算，r002 是新紀錄。
- 切換 lens−/lens+/lens+0.2 µm：標題、介質與位置都改對；不誤畫元件 T。
- 開啟沒有 Ey 的來源：Ey 明示未提供；不宣稱做了双偏振共同設計。
- 選擇純相位加同面振幅整形：提示限制，不接受不可能的目標且顯示成功。
- 使用其他波長、資料庫行序打亂：幾何圖不變；缺柱子則停下並列出原因。
- 多波長只有單波長光源：必須確認沿用場的假設，結果與匯出有紀錄。
- 點選取消：UI 仍可操作，不把部分計算標成完成；保留已保存最佳設計。
- 513×1025 匯出 ZBF：原樣輸出被阻止；補零需確認且場座標與 metadata 一致。
- MAT 讀回 complex128 Ex/Ey、dx/dy/Nx/Ny；ZBF 讀回與原場在容許誤差內一致。
- Ex/Ey 振幅相位/XZ 匯出：標題、單位、色階、colorbar 長度在投影片尺寸下驗證。
- 缺少私人檔案的機器重開專案：指出哪個資產缺失並提供重新定位，沒有原始堆疊錯誤。

## 11. 待試操作後決定（不阻止草稿）

- 預設 Ex/Ey 並排或各自 amplitude/phase 並排：以互動草稿比較。
- 常用波長、光路與匯出位置：可存為使用者範本，不寫死在程式。
- 「準直」成效門檻與最佳化目標面/束寬：需要實際需求或量測標準，不能由 GUI 猜。
- scalar meta-atom 資料庫的通道、單位、介面與強度定義：以資料來源為準。
